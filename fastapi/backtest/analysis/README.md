# 실효 지급률 변동 요인 분석 자료 (프로덕션 미채택)

이 디렉토리의 코드는 **엔진이 아니다.** 실적 데이터에서 실효 지급률
(연금월액 / (평균기준소득월액 x 재직연수))이 어떤 변수를 따라 움직이는지
탐색한 분석 프로토타입이며, 한때 프로덕션(`app/services/`)에 반영됐다가
철회됐다(커밋 c6b2fbf 도입 -> 4f59181 철회).

## 왜 철회했는가

`effective_rate_model_30param.py`는 재직연수 구간별 요율(knot 12개), 소득탄력성,
퇴직연도 보정, 퇴직연령 보정, 학교급x직구분 배수(15개) — 총 약 30개 계수를
2020~2025년 **퇴직자** 실적 40,719건에 직접 적합한 것이다. 5-fold 교차검증
기준 백테스트 구간 적중률은 80.39%까지 올랐다(`calibration_report_30param.md`).

문제는 이 모형이 서비스하는 대상과 학습한 표본이 다르다는 것이다.
`/api/employees/simulate`는 **미래에 퇴직할 재직자**를 예측하는데, 이 모형이
학습한 재직연수별 요율 하락 패턴의 상당 부분은 "재직기간 중 2009년 이전
구간(법정 산정기초가 평균보수월액이라 평균기준소득월액보다 낮음) 비중이 클수록
실효율이 낮다"는 구조를 반영한 것으로 추정된다. 2009년 이전 재직기간이 0인
미래 퇴직자(예: 2055년 퇴직, 33년 근속)에게 이 요율 곡선을 그대로 적용하면
체계적으로 과소추정한다 — 정량 비교는 `future_extrapolation.md` 참조.

계수 자체도 법령상 근거가 없다(순수 데이터 적합값). 반면 프로덕션에 채택한
tranche+α 모형(`app/services/pension_rate_model.py`)은 파라미터가 1개
(2009년 이전 구간 환산계수 α)뿐이고, 나머지는 전부 확정된 법정 연도별 지급률
(`backtest/config/tranche_rates.py`)이라 미래 퇴직자에게도 구조적으로
외삽 가능하다.

## 이 자료를 어떻게 쓸 것인가

"엔진에 넣을 계수"가 아니라 "법정 산식이 놓친 것으로 보이는 패턴들의 목록"으로
읽는다. 방향은 전부 법정 산식 요소로 설명 가능하다:

- 재직연수 ↑ -> 실효율 ↓ : 2009년 이전 구간 비중 증가 (-> tranche+α가 흡수)
- 소득 ↑ -> 실효율 ↓ : 소득재분배(A값) 흔적으로 추정 (외부 법령 파라미터 미확보, 미구현)
- 퇴직연도 ↑ -> 실효율 ↓ : 법정 지급률 인하 스케줄과 방향 일치 (tranche가 이미 반영)
- 학교급x직구분 간 최대 ±5% 차이 : 원인 미상, 법령상 근거를 찾지 못함

## 파일

- `effective_rate_model_30param.py` — 철회된 프로덕션 코드 원본(당시 경로: `app/services/pension_rate_model.py`)
- `phase6_calibrated_30param.py` — 위 모형을 평가한 백테스트 스크립트(당시 경로: `backtest/scripts/phase6_calibrated.py`)
- `calibration_report_30param.md` — 위 스크립트의 산출 리포트(당시 경로: `backtest/reports/calibration_report.md`)

이 파일들은 더 이상 어떤 프로덕션 코드에서도 import되지 않는다. 재실행하려면
당시 경로로 되돌려야 하며(상대 import가 그 경로를 전제로 한다), 그럴 필요가
생기면 git 이력(커밋 c6b2fbf)에서 전체 diff를 확인할 것.
